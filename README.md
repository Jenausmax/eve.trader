# rules — общий набор правил для агентов

Канонические правила кодстайла, архитектуры и процесса, **общие для всех
проектов**. Один источник вместо копий, разошедшихся по репозиториям.

Набор читают агентные харнессы (Claude Code, pi-coding, Cursor, Windsurf) —
каждый файл несёт frontmatter с `description` / `globs` / `always`, по которому
харнесс решает, грузить правило в контекст или нет. Формат описан в
[`csharp/rules-format.md`](csharp/rules-format.md).

## Что внутри

| Раздел | Про что |
|--------|---------|
| `csharp/` | C#: архитектура, нейминг, async, API, EF, тесты, структура проектов |
| `typescript/` | фронтенд: React 19, TanStack Query/Router, Tailwind + токены, bun + i18n |
| `process/` | режим работы агента: worktree, оркестрация, запрет dev/watch, секреты, регистрация проектов |
| `observability/` | OTel-контракт (наполняется второй волной) |

Правила **не** содержат проектной специфики: путей конкретного репозитория,
имён его сборок, фаз, ADR. Всё это живёт у потребителя.

## Как подключается — git subtree

Общий набор въезжает в потребителя как `subtree` в `.agents/rules/`:

```bash
# первый раз
git remote add rules <url-этого-репозитория>
git subtree add --prefix=.agents/rules rules master --squash

# обновиться до свежих правил
git subtree pull --prefix=.agents/rules rules master --squash
```

Subtree, а не submodule: файлы физически лежат в репозитории потребителя, значит
агент читает их без дополнительных шагов, а свежая копия репозитория работает
сразу после `git clone`.

## Как править — ЗДЕСЬ, не у потребителя

> **Правка общего файла на месте у потребителя будет потеряна.** Следующий
> `git subtree pull` перезапишет файл версией из этого репозитория. Тихо, без
> конфликта — если правка успела попасть в коммит потребителя, `pull` разведёт
> её как merge, и итог зависит от везения.

Порядок:

1. Правишь файл **в этом репозитории**, коммитишь.
2. Перегенерируешь манифест: `node scripts/manifest.mjs --write`.
3. У потребителей — `git subtree pull` (или `git subtree push` из потребителя,
   если правка родилась там; но тогда её всё равно надо влить сюда первой).

## Локальные правила потребителя — префикс `local-`

Правило, верное только для одного репозитория (его слои, его гейты, его
кодогенерация, его ADR), в общий набор **не едет**. Оно лежит рядом, в том же
`.agents/rules/`, с префиксом `local-`:

```
.agents/rules/
├── csharp/            ← subtree, общее — правится только в rules-репозитории
├── typescript/        ← subtree
├── process/           ← subtree
├── observability/     ← subtree
├── local-analyzer-catalog.md      ← локальное: набор анализаторов этого репо
├── local-project-layers.md        ← локальное: слои этого репо
└── process/local-migrations.md    ← локальное: процесс миграций этого репо
```

Префикс — визуальный маркер: файл без него правится наверху, файл с ним —
на месте. Общее правило, у которого в конкретном проекте свой механизм проверки,
остаётся общим; механизм описывается в локальном файле.

## MANIFEST.json — проверка, что общий файл не правили на месте

[`MANIFEST.json`](MANIFEST.json) — sha256 каждого файла набора:

```json
{
  "schemaVersion": 1,
  "algorithm": "sha256",
  "generated": "2026-08-16",
  "fileCount": 98,
  "files": {
    "csharp/api-design.md": "e3b0c442…",
    "typescript/README.md": "a1d0c6e8…"
  }
}
```

Потребитель сверяет свою копию с манифестом и видит файлы, отредактированные
локально вместо правки наверху:

```js
import { createHash } from 'node:crypto';
import { readFileSync } from 'node:fs';

const manifest = JSON.parse(readFileSync('.agents/rules/MANIFEST.json', 'utf8'));
for (const [rel, expected] of Object.entries(manifest.files)) {
  const actual = createHash('sha256')
    .update(readFileSync(`.agents/rules/${rel}`))
    .digest('hex');
  if (actual !== expected) console.error(`drift: ${rel}`);
}
```

В самом репозитории то же самое делает `node scripts/manifest.mjs` (без
аргументов — проверка, `--write` — перегенерация). Хеши считаются по байтам, а
`.gitattributes` фиксирует LF, поэтому результат одинаков на всех платформах.

## Статус сборки

Набор собран из двух разошедшихся канонов — глобального и проектного. Сначала
приехали файлы без противоречий: одна версия строго богаче, либо версии
дополняют друг друга, либо файл существовал в единственном экземпляре.

Затем сведены те, где версии **противоречили**. Решения приняты владельцем и
записаны в истории коммитов; краткий свод:

| Позиция | Решение |
|---|---|
| Кортежи | запрет во всём пользовательском коде, не только в public API |
| Primary constructors | требуются для всех sealed-классов, не только для DI |
| `ThrowIf*` | запрещено всё семейство, а не один `ArgumentNullException` |
| Анализаторы | сокращённый набор: IDE + async |
| `JsonSerializerOptions` | DI там, где есть контейнер; именованный синглтон только там, где его нет |
| Стек тестов | зафиксирован выбор библиотек и причина; номера версий — у потребителя |
| Гейт `ConfigureAwait` | запрет общий, механизм принуждения объявляет потребитель |

Общий принцип разбора: в набор попадает **выбор и его причина**, а локальные
факты — версии пакетов, имена сборок, пути, номера ADR — остаются у
потребителя. Правило, называющее версию, устаревает в день её подъёма и
начинает противоречить репозиторию молча.
