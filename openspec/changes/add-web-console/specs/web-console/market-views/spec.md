## Purpose

Экраны рынка: обзор, детализация по паре «тип и локация», графики цены, объёма, спреда и
глубины — рыночные ряды читаются глазами по графику, а не по таблице в терминале.

## ADDED Requirements

### Requirement: Обзор рынка и детализация по паре

Консоль SHALL показывать обзор наблюдаемых рынков и детализацию по паре «тип и
локация». Детализация MUST содержать ряды дневной истории и текущее состояние стакана
по признакам: лучшие цены обеих сторон, спред и глубину.

#### Scenario: Переход от обзора к паре

- **WHEN** оператор выбирает пару в обзоре
- **THEN** открыт экран детализации этой пары с рядами истории и состоянием стакана

#### Scenario: По паре нет наблюдений

- **WHEN** открыта пара, по которой наблюдений в выбранном интервале нет
- **THEN** экран сообщает об отсутствии наблюдения, а не показывает пустой график

### Requirement: Пропуск изображается пропуском

График MUST NOT подменять отсутствующее значение нулём или соединять точки через
ненаблюдавшийся интервал. Отсутствие стороны стакана, ненаблюдавшийся такт и нулевая
величина MUST быть визуально различимы.

#### Scenario: В ряду есть ненаблюдавшийся интервал

- **WHEN** в выбранном интервале часть тактов не наблюдалась
- **THEN** на графике этот участок показан разрывом, а не прямой между соседями

#### Scenario: Одной стороны стакана нет

- **WHEN** по паре нет ордеров на покупку
- **THEN** лучшая цена покупки показана как отсутствующая, а не как ноль
- **AND** спред не показан

### Requirement: Происхождение показанного видно

Экран SHALL называть момент наблюдения, из которого взято показанное состояние, и
версию статических данных. Значения, полученные из частичного наблюдения, MUST быть
помечены неполными на самом экране.

#### Scenario: Состояние стакана показано

- **WHEN** открыт экран детализации
- **THEN** указан момент наблюдения и версия статических данных

#### Scenario: Показано значение частичного наблюдения

- **WHEN** в интервал попало частичное наблюдение
- **THEN** его точки на графике помечены неполными

### Requirement: Ряды выдерживают объём наблюдений

Экраны SHALL оставаться отзывчивыми на рядах, которые даёт конвейер за месяц наблюдения
пары с минутным шагом. Прореживание ряда для отображения допустимо и MUST быть объявлено
на экране: молчаливое прореживание превращает выброс в отсутствующее событие.

#### Scenario: Запрошен длинный интервал

- **WHEN** оператор выбирает интервал в месяц по паре с частым наблюдением
- **THEN** график отрисован без зависания интерфейса

#### Scenario: Ряд проряжен для отображения

- **WHEN** точек в ряду больше, чем отображается
- **THEN** экран сообщает, что ряд проряжен, и называет шаг
