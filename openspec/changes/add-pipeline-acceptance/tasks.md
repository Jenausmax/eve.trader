## 1. Наблюдаемость

- [ ] 1.1 Реализовать метрики по контракту `observability/diagnostics.md`: число запросов, трафик, доля ответов «не изменилось», длительность наблюдения региона, остаток бюджета ошибок, доля изменившихся ордеров за наблюдение, число пропусков источника — проверка: integration-тест сценария `specs/market-observation/intake` §«Расход ресурсов наблюдаем»; метрики видны в экспорте

## 2. Замеры

- [ ] 2.1 Снять фактические замеры и сопоставить с бюджетом из `design.md` §«Что с чем сверяется»: пиковая память, длительность наблюдения крупнейшего региона, объём событий за сутки, объём после конвертации окна архива — проверка: замеры записаны; расхождение больше чем втрое — повод пересмотреть бюджет, а не удалять сырьё

## 3. Приёмка

- [ ] 3.1 Прогнать приёмочный сценарий: перестроить признаки за материализованный интервал из сырья и сверить с записанными — проверка: совпадение полное для полных наблюдений, отчёт о покрытии без незапланированных пробелов; выбранный интервал содержит смену версии статических данных и досинхронизацию задним числом

## 4. Команды оператора

- [ ] 4.1 Реализовать команды `EveTrader.Cli`: запуск сбора, импорт интервала, отчёт о покрытии и материализации, осмотр фактов, реплей — проверка: каждая команда запускается и печатает непустой результат

## 5. Бумага

- [ ] 5.1 Закрыть бумагу изменения — проверка: `openspec validate add-pipeline-acceptance --strict` без замечаний, запись в `CHANGELOG.md` на месте, `dotnet build EveTrader.slnx -c Debug` зелёный
