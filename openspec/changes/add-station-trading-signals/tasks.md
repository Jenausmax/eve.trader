## 1. Комиссии и параметры прогона

- [ ] 1.1 Типы модели комиссий в домене: брокерская комиссия обеих сторон, налог с продажи, плата за перестановку; значений по умолчанию нет — проверка: unit-тест на маржу после комиссий, прогон без объявленных ставок отклоняется
- [ ] 1.2 Именованный набор параметров правила (пороги + ставки) с устойчивым именем — проверка: сценарий `market-signals/station-trading` §«Набор параметров именован»; два набора на одном интервале дают различимые сигналы

## 2. Ряды признаков в домене

- [ ] 2.1 Определение ряда: окно, шаг, перечень исходных наборов фактов; определение входит в ключ факта — проверка: сценарии `market-signals/feature-series` §«Ряд признака несёт своё определение»
- [ ] 2.2 Разрешение покрытия окна: ненаблюдавшийся интервал внутри окна — признак не порождается; частичное наблюдение — порождается помеченным неполным — проверка: сценарии §«Признак по неполному окну не порождается», все три
- [ ] 2.3 Признаки по событиям: наблюдённый исполненный объём, число перестановок без пополнений NPC, доля исчезновений с предшествующим исполнением, длительность удержания лучшей цены, число ордеров в пределах порогов — проверка: сценарии §«Признаки станционной торговли выводятся из событий»
- [ ] 2.4 Детерминированность вычисления: порядок обхода не зависит от хеш-таблицы, выдача упорядочена — проверка: unit-тест дважды считает один интервал и сверяет побитово

## 3. Материализация рядов

- [ ] 3.1 Набор фактов рядов в озере с двумя временами, версией статических данных и подтверждением покрытием — проверка: integration-тест пишет и читает ряд; строка без записи покрытия в выдачу не попадает
- [ ] 3.2 Чтение ряда на момент знания через порт плоских строк; вычисление вне хранилища — проверка: сценарии §«Ряды выводимы из фактов и читаются на момент времени» и §«Ряды считаются вне хранилища»
- [ ] 3.3 Перестройка ряда за интервал даёт исходный результат — проверка: сценарий §«Ряд перестроен из фактов» на озере из архива EVE Ref
- [ ] 3.4 Воркер материализации рядов отдельным воркером со своими счётчиками — проверка: тест разделения воркеров расширен, наборы счётчиков не пересекаются

## 4. Правило станционной торговли

- [ ] 4.1 Вычисление маржи после комиссий; при неположительной марже сигнала нет — проверка: сценарии `market-signals/station-trading` §«Маржа считается после комиссий»
- [ ] 4.2 Условия правила поверх рядов: скорость оборота, глубина конкуренции, давление перестановок — проверка: unit-тесты на каждое условие по отдельности и на их совокупность
- [ ] 4.3 Три исхода рассмотрения пары различимы: сигнал, данных хватило и условия не выполнены, данных не хватило — проверка: сценарии §«Сигнал не порождается на недостаточных данных», оба
- [ ] 4.4 Обоснование в каждом сигнале: значения признаков и пороги — проверка: сценарий §«Сигнал несёт обоснование»

## 5. Сигнал как факт и команда оператора

- [ ] 5.1 Набор фактов сигналов: оба времени, версия статических данных, имя набора параметров, неизменяемость — проверка: сценарии §«Сигнал — факт озера», оба
- [ ] 5.2 Команда `signals` — сигналы за интервал с обоснованием и причинами молчания — проверка: команда запущена на настоящих данных и напечатала непустой результат
- [ ] 5.3 Сигнал не содержит исполняемых в игре указаний — проверка: сценарий §«Сигнал — рекомендация, а не действие»

## 6. Бэктест

- [ ] 6.1 Прогон правила на истории тем же кодом правила, с подменой момента решения и горизонта чтения — проверка: тест сверяет, что боевой и историчный прогон идут через один тип правила
- [ ] 6.2 Чтение строго на момент решения: факт, узнанный позже, в расчёт не входит — проверка: сценарии `market-signals/backtest` §«Бэктест читает строго на момент решения», оба; интервал прогона содержит досинхронизацию задним числом
- [ ] 6.3 Определение исхода по наблюдённым фактам с названным горизонтом; непокрытый горизонт даёт неизвестный исход — проверка: сценарии §«Исход сигнала определяется наблюдёнными фактами»
- [ ] 6.4 Отчёт с метриками качества, базовой линией «не торговать» и долей неизвестных исходов — проверка: сценарии §«Отчёт называет качество и базовую линию», оба
- [ ] 6.5 Воспроизводимость прогона побитово, включая порядок — проверка: сценарий §«Прогон повторён»
- [ ] 6.6 Отчёт о прогоне записывается фактом; сравнение наборов параметров идёт по отчётам — проверка: сценарий §«Сравнение наборов параметров»
- [ ] 6.7 Прогнать бэктест на настоящих данных за интервал не меньше месяца и записать результат в `design.md` — проверка: отчёт получен, метрики и базовая линия названы, доля неизвестных исходов записана; убыточный результат записывается как есть
