> **Отклонения, принятые при реализации** (разбор — в `design.md`):
>
> - Дневная история партиционируется по **календарной дате**, а не по времени получения,
>   и регион идёт колонкой, а не партицией. Исходный довод («переписывание партиции»)
>   отпал вместе с реализацией озера, а цена оказалась измеримой: до 975 файлов на одни
>   сутки данных против одного.
> - Одно наблюдение архива накрывает все регионы файла, поэтому файл покрытия несёт
>   несколько записей — по одной на регион. Норма «запись по каждой попытке наблюдения
>   региона» соблюдена.
> - Заведены две команды `EveTrader.Cli` (`import-history`, `history-stats`). Полный
>   набор команд оператора остаётся за `add-pipeline-acceptance`; без запускаемого входа
>   задачу 3.1 выполнить нечем.

> **3.1 и 4.1 открыты: импорт идёт.** Полная глубина — 8387 суток, скорость ~10 суток/мин
> при двух потоках, то есть около тринадцати часов. Упор в источник, а не в нас: `curl` на
> те же файлы даёт 2.5–4.7 с на файл, CPU занят на 3.5 %. Импорт идемпотентен и
> продолжается с места обрыва.
>
> Озеро — `~/eve.trader-data/lake`, лог — `~/eve.trader-data/import-*.log`. Числа для
> §Open Questions снимаются командой `history-stats` по завершении; промежуточные замеры
> уже записаны в `design.md` §Замеры прогона.
