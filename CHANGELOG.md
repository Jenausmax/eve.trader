# Changelog

Журнал изменений eve.trader. Запись появляется вместе с изменением, а не после тега —
`process/docs-completeness.md`. Каждая запись ссылается на свой OpenSpec change.

Формат: обратный хронологический порядок, новое сверху.

## Не выпущено

### Свёртка наблюдений в события и признаки

Change: [`add-order-event-derivation`](openspec/changes/add-order-event-derivation/)

- **Шесть видов событий жизни ордера** с разметкой времени: перестановка несёт точный
  момент из `issued`, исполнение — интервал между наблюдениями, появление даёт момент
  создания только при достаточно частом шаге.
- **Пополнение склада NPC отделено от перестановки** — иначе каждое пополнение попало бы
  в обучение как действие конкурента.
- **Исчезновение подтверждается окном** последовательных полных наблюдений; причина в
  событии не домысливается, но истечение вычислимо из `issued` и длительности.
- **Признаки стакана в той же проходке**; охват признаков — отдельная настройка,
  отсутствие стороны записано отсутствием, а не нулевой ценой.
- **Суточные чекпойнты** и восстановление состава стакана из чекпойнта и событий,
  только по полным наблюдениям. Property-тест сверяет признаки, пересчитанные по
  восстановленному стакану, с посчитанными в проходке.
- **Горячий путь без аллокаций**: 504 байта на наблюдение независимо от размера стакана,
  294 мс на проходку миллиона ордеров, структура ордера 56 байт.

### Импорт дневной истории

Change: [`add-daily-history-import`](openspec/changes/add-daily-history-import/)

- **Источник назван: EVE Ref** (`data.everef.net/market-history/`), сутки одним
  глобальным файлом на все регионы, глубина с 1 октября 2003 года. Раскладка и лицензия
  записаны в `design.md`.
- **Единый вход двумя источниками.** Архив и живой ESI реализуют один порт
  `IMarketHistorySource`, поэтому «факты неразличимы» — проверяемое утверждение, а не
  декларация: происхождение известно только из журнала покрытия.
- **Вежливость к источнику**: параллелизм ограничен двумя потоками, каждый запрос
  условный по времени изменения; неизменившийся файл не скачивается вовсе.
- **Би-темпоральность на живых данных.** Время получения берётся из колонки
  `http_last_modified` — момента, когда источник узнал строку от ESI. Досинхронизация
  дописывает только новое и сохраняет прежние версии.
- **Дневная история партиционируется по календарной дате, регион — колонка.**
  Отклонение от первоначального решения; разбор — в `design.md`.
- **Разбор терпит четыре поколения формата источника**, включая перестановку `highest` и
  `lowest` в файлах 2019 года: колонки читаются по именам, а не по местам.
- Заведены первые команды `EveTrader.Cli`: `import-history` и `history-stats`.

### Би-темпоральное озеро фактов

Change: [`add-bitemporal-fact-lake`](openspec/changes/add-bitemporal-fact-lake/)

- **Факт — строка, подтверждённая записью покрытия.** Протокол записи: данные во
  временный файл, атомарное переименование, запись покрытия последней. Отсюда же
  идемпотентность приёма и уборка неподтверждённого после аварии.
- **Два времени на каждой строке**: время события (момент либо интервал, различаемые
  явно) и время получения. Чтение на момент не видит строк, записанных позже.
- **Журнал покрытия с тремя состояниями** — наблюдалось, не материализовано, не
  наблюдалось — и доменный резолвер, который их различает по журналу, реестру и каталогу
  источника.
- **Реестр материализованных интервалов** как единственное основание для ответа о
  наличии данных локально; окно локального хранения — настройка, сдвиг окна делает
  интервалы восполнимыми, не трогая данные.
- **Два раздельных порта чтения**: плоские строки для признаков и обучения, агрегаты для
  отчётов оператору. Недоступность агрегатов домену и плоской стороне закреплена тестом
  архитектуры.
- **Неизменяемость фактов**: срок хранения отклоняется для сырья, удаление разрешено
  только производным наборам.
- Раскладка озера, партиционирование по дате наблюдения и региону, сортировка внутри
  файла по ключу факта. Отсечение партиций проверяется планом DuckDB.

### Скелет решения и гейты

Change: [`bootstrap-solution-skeleton`](openspec/changes/bootstrap-solution-skeleton/)

- Заведено решение `EveTrader.slnx` и централизованная сборка: `Directory.Build.props`,
  `Directory.Build.targets`, `Directory.Packages.props`, `global.json` (SDK 10.0.401),
  `.editorconfig`.
- Созданы проекты слоёв по `csharp/local-project-layers.md`: `EveTrader.Domain`,
  `EveTrader.Application`, `EveTrader.Infrastructure.{Esi,Facts,Archive,Sde}`,
  `EveTrader.Cli`.
- Гейт сборки — одна команда `dotnet build EveTrader.slnx -c Debug`: компиляция,
  анализаторы и проверка форматирования через `EveTrader.Build.Tools`.
- Законы слоёв исполняемы: `tests/architecture/` проверяет направление ссылок и запрет
  ссылок между инфраструктурными проектами по графу `ProjectReference`, NetArchTest —
  зависимости типов домена.
- Запрет системных часов в домене закреплён `BannedApiAnalyzers`: `DateTime.UtcNow`,
  `DateTime.Now`, `DateTimeOffset.UtcNow`, `DateTimeOffset.Now`, `TimeProvider.System`
  роняют сборку.
- Заведён `ScheduledWorkerBase` с расписаниями `IntervalSchedule`,
  `AdaptivePollSchedule`, `StartupSchedule`, DI-scope на цикл и эмиссией счётчиков по
  `[Counter]`; под него — минимальный диагностический контур `IDiagnosticSource` поверх
  `Meter` и `ActivitySource`.
- Тестовый стек зафиксирован: xUnit v3 на Microsoft.Testing.Platform, Shouldly,
  NSubstitute, NetArchTest.Rules, Coverlet.
