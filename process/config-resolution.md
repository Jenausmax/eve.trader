# Config resolution — один параметр, один источник

> `<PREFIX>` в этом правиле — префикс переменных окружения, который объявляет
> сам проект (например `HYBRID`). Важен не он, а то, что префикс ОДИН и
> отличает переменные приложения от всего остального в окружении.

Правило про то, **откуда приложение реально берёт значение** и почему
«я поправил файл, а в кластере старое» — не мистика, а предсказуемое
следствие порядка провайдеров.

> **Инвариант: у каждого параметра ровно ОДИН источник истины.**
> Дублирование значения в двух местах — дефект, даже когда значения
> совпадают. Совпадают они только до первой правки одного из двух.

## 1. Порядок приоритета — последний побеждает

```
1. appsettings.json                  ← базовый, УЕЗЖАЕТ В ОБРАЗ вместе со сборкой
2. appsettings.{Environment}.json
3. appsettings.Local.json            ← только локальная разработка
4. <PREFIX>_* переменные окружения     ← включая всё, что пришло из k8s Secret
```

Пункт 4 перекрывает всё выше. Практическое следствие: **значение из
Secret'а всегда сильнее значения из файла в образе.** Если в Secret'е
лежит мусор, корректное значение в `appsettings.json` не спасёт — оно
проиграет.

Провайдер `<PREFIX>_*` (собственный провайдер конфигурации проекта) меняет
**одинарное** подчёркивание на `:`

```
<PREFIX>_DSP_API_BASEURL   →   dsp:api:baseurl     ✅
<PREFIX>_DSP__API__BASEURL →   dsp::api::baseurl   ❌ не сработает
```

Двойное подчёркивание не работает: дефолтный env-провайдер ASP.NET
отключён через `UseHybridEnvironmentVariablesOnly`.

## 2. Что где лежит по правилам

| Что | Где можно | Где НЕЛЬЗЯ |
|---|---|---|
| Секреты (токены, пароли, ключи) | k8s Secret, Consul | `appsettings*.json`, любые `values*.yaml` — они уезжают в git **и** в образ |
| Несекретный env-специфичный конфиг (адреса, режимы) | `deploy/hybrid/<env>.yaml` | базовый `appsettings.json` — он общий для всех окружений |
| Дефолты для разработки | базовый `appsettings.json` | — |

Базовый `appsettings.json` **не место для прод-значений**: он один на все
окружения и лежит в git. Если прод-значение оказалось там — это либо
временное решение, которое нужно проговорить в комментарии рядом, либо
ошибка.

## 3. Перед коммитом любого изменения конфигурации

Один `grep` по имени параметра во **всех** источниках сразу:

```bash
grep -rn "DSP_API_BASEURL\|dsp:api:baseurl\|\"BaseUrl\"" \
  <путь к appsettings> <путь к deploy>
```

- параметр встретился **в одном** источнике — хорошо;
- **в двух и более** — убрать дубль. Если дубль осознанный (переходный
  период), рядом обязателен комментарий: кто побеждает и когда дубль уйдёт.

Не полагаться на CI: `EXPECTED_KEYS` в
Проверка в CI проверяет только **наличие**
ключа, но не пригодность значения. Ключ с мусором проходит проверку зелёным.

## 4. Эксплуатационные правила k8s Secret

1. **Значения кладём через `stringData`, а не `data`.** `data` требует
   base64, и ручная раскладка регулярно даёт **двойное** кодирование:
   значение кодируют руками, а API кодирует ещё раз. Симптом — строка
   длиной `ceil(N/3)*4` вместо ожидаемых `N` символов, и полезная нагрузка
   вида `ZXlKaGJHY2lP…` (это base64 от `eyJhbGciO…`).
2. **После правки Secret'а обязателен `rollout restart`.** Env из
   `envFrom.secretRef` фиксируется при создании пода — живой под новое
   значение не увидит никогда.
3. **ArgoCD применяет values с задеплоенной ревизии, а не из рабочей
   копии.** Правка файла в ветке не меняет ничего в кластере до релиза.
   Что применено — смотреть в `Application.spec.sources[].targetRevision`.
4. **Образ содержит `appsettings.json` того коммита, из которого собран.**
   Образ в проде и `develop` расходятся тем сильнее, чем старше тег.

## 5. Ошибка внешнего API ≠ ошибка доставки

Отдельная ловушка того же класса: неверный конфиг может не давать ни одной
красной строки. Ответ `401` от внешнего API логируется как обычный
`Result: '401'`, а работа-обёртка при этом рапортует об успехе
(`AssemblyWorker delivered 1 model(s) … DSP IsOk=(null)`). **Тишина в
логах и метриках не доказывает, что доставка работает.** Если добавляете
исходящий вызов — проверяйте, что не-2xx превращается в наблюдаемую
ошибку, а не в `null`.

## 6. Когда значение «лагает» — диагностическая цепочка

Не угадывать и не править файлы наугад. Пошаговая процедура с командами:
[`docs/services/config-troubleshooting.md`](../../../docs/services/config-troubleshooting.md).

Порядок в одну строку: **что видит процесс → что в Secret → что применено
ArgoCD → что в образе → что в логах.** Первый шаг всегда «что фактически
в поде», а не «что написано в репозитории».
