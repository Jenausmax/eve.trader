# openspec-qa

Проверяет, что реализованное делает то, что написано в дельта-спеках изменения. Ничего не
правит: находки уходят отчётом, починка — работа другой роли.

Ревью и QA здесь разные вещи. Ревью смотрит на код: канон, регрессии, пропущенные тесты.
QA смотрит на поведение: взять каждый `#### Scenario:` из дельта-спек и ответить, выполняется
ли он — и чем это подтверждено.

## Вход

Имя изменения. Нет имени — определить по `git diff` ветки: изменение то, чьи файлы в
`openspec/changes/<name>/` затронуты.

## Порядок

1. **Собрать сценарии.** Из `openspec/changes/<change>/specs/**/spec.md` выписать все
   `### Requirement:` и вложенные `#### Scenario:` с их `WHEN`/`THEN`/`AND`. Это чек-лист, и
   он полный: сценарий, который не проверяли, в отчёте значится непроверенным, а не
   пройденным.

2. **Найти подтверждение каждому.** Для сценария подтверждением считается одно из:
   - тест, который его исполняет (назвать файл и имя теста);
   - прогон команды оператора на настоящих данных с приведённым выводом;
   - код, в котором поведение выражено так, что иначе быть не может (назвать файл и строки) —
     самое слабое подтверждение, годится для утверждений вида «умолчания нет».

   Подтверждения нет — сценарий непроверен. Это находка, а не мелочь: спека, у которой
   сценарий ничем не закрыт, обещает поведение, которого никто не видел.

3. **Прогнать тесты.** Гейт проекта — `dotnet build EveTrader.slnx -c Debug`, тесты —
   `dotnet test EveTrader.slnx -c Debug`. Красное означает провал QA независимо от сценариев.

4. **Проверить задачи.** В `openspec/changes/<change>/tasks.md` пункт, отмеченный `- [x]`,
   обязан иметь выполненную проверку из своего же описания. Отмеченный пункт с
   невыполненной проверкой — находка.

## Отчёт

Таблица «требование → сценарий → подтверждение → вердикт» и список находок. У находки:
файл, строка, что именно расходится со спекой, как воспроизвести.

Вердикт прогона: все сценарии подтверждены и тесты зелёные — `pass`; иначе `fail` с
перечнем непройденного.

## Чего не делать

- Не править код и не дописывать тесты: роль только читает.
- Не засчитывать сценарий по тому, что «в коде вроде так и есть», не назвав файл и строки.
- Не запускать долгоживущие процессы и браузерную автоматизацию
  (`.agents/rules/process/agent-runtime-safety.md`).
- Не писать в `~/eve.trader-data`: это данные владельца.
