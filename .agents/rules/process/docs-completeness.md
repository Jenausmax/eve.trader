# Documentation completeness — фича едет со своей бумагой

Код без бумаги — недоделанная работа, сколько бы гейтов он ни прошёл. Правило закрывает
повторяющийся отказ: агент закрывает фичу («build зелёный, MR слит»), а OpenSpec change,
запись в changelog и STATE выясняются задним числом — в момент, когда тег уже нельзя
переиграть.

## 1. Что входит в «бумагу» фичи

| Артефакт | Когда живёт | Где |
|---|---|---|
| OpenSpec change (`proposal` + `tasks` + спек-дельты) | всей фичой | `openspec/changes/<slug>/` |
| Запись в changelog релиза | с момента слияния фичи | `deploy/docs/pages/changelog.md` (SDK-пара) / аналог продукта |
| Запись в `.agents/STATE.md` | продуктовые репо | ветки/типы/остатки фичи |
| Ратификация mcp-классификаций | если менялась HTTP/MCP-поверхность | владелец в ревью, не агент |

Жанр change'а «задним числом честно» (описывает уже реализованное) **допустим** —
прецеденты `rbac-audit-log`, `audit-ef-profiles`. Отсутствие бумаги — нет.

## 2. Кто пишет

- **Воркер/исполнитель фичи** — change и changelog-черновик едут теми же коммитами/ ветками,
  что и код, или первым follow-up до слияния. Бриф воркера содержит поле `Docs:` (что из
  таблицы выше воркер закрывает сам).
- **Оркестратор** — перед финальным отчётом «фича готова» сверяет таблицу §1; дыра
  закрывается до отчёта, а не после.
- **Релизный агент** (скиллы `hybrid-release-*`) — шаг перед тегом: `git log
  <last-tag>..master` — каждая содержательная волна соотносится с change'ом; нет —
  оформить до тега. Тег необратим: опоздавшая бумага живёт в следующем релизе.

## 3. Проверка одной командой

```bash
git log <last-tag>..master --oneline          # волны коммитов
ls openspec/changes/ | grep -v archive        # какие change'ы заявлены
```

Волна без change'а — блокер релиза, а не замечание ревью.

## Anti-patterns

- «Напишу спеку потом» — потом наступает после тега, и запись ложится в чужой номер.
- Чейдж с галочками, не совпадающий с деревом (`[x]` на отсутствующем в коде) — хуже
  отсутствующего: он врёт уверенно.
- Changelog-запись «война правок» из чужих MR без записи автора фичи — каждая фича
  релиза пишется тем, кто её вёз, или релизным агентом с его слов.
